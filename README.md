## 미리보기 모드

config.js의 endpoint가 비어 있으면 미리보기입니다. ID는 PREVIEW-P01 형식이며 브라우저 내에서만 발급합니다. 실제 시트에 저장되었다고 표시하지 않습니다. 응답은 해당 기기 localStorage에 남습니다. 새로고침 시 sessionStorage의 진행 상태를 복원합니다.

## 실제 Google Sheets 연결

1. 전달한 스프레드시트에서 확장 프로그램 → Apps Script를 엽니다.
2. Code.gs 내용을 붙여넣습니다. 스프레드시트 ID는 이미 설정되어 있습니다.
3. 배포 → 새 배포 → 웹 앱을 선택합니다. 실행 주체는 본인, 접근 권한은 참가자가 로그인 없이 접속 가능한 ‘모든 사용자’로 설정합니다. Google 계정 권한 승인과 배포는 소유자가 진행합니다.
4. 발급된 /exec URL을 config.js의 endpoint에 넣습니다.
5. UT_responses 탭이 자동 생성됩니다. 시트에 공개 편집 권한을 줄 필요는 없습니다.

서버에서 LockService로 발급을 직렬화하므로 여러 기기에서도 P01, P02 순번이 중복되지 않습니다. 중단한 참가자도 번호를 사용하므로 완료 응답 사이에 결번이 있을 수 있습니다. 같은 세션 재전송은 기존 행을 갱신합니다. 연결 실패 시 재시도할 수 있고 성공 확인 후에만 완료를 표시합니다. 임의 외부 요청을 제한하는 인증/스팸 방지는 아직 없어 소규모 UT용입니다.

## 배포

GitHub Pages 배포 파일: index.html, style.css, survey.js, config.js, prototype/ 전체. 모든 경로는 상대 경로로 하위 경로 배포를 지원합니다. Code.gs, README.md, prototype-src/는 배포할 필요가 없습니다.

프로토타입 수정: prototype-src에서 npm install 후 npm run build. 빌드 결과는 prototype/에 생성됩니다. 원본 Figma 내보내기 파일은 변경하지 않았습니다.

연령대는 age_group에 저장하며 기존 age 열은 과거 데이터 보존용으로 유지합니다. 신규 응답의 age는 비워 둡니다. 이용 상황은 usage_situations, 기타는 usage_other에 저장합니다. usage_question_type은 experienced(경험자) 또는 expected(미경험자)입니다. Apps Script를 이미 배포했다면 Code.gs를 교체하고 새 버전으로 다시 배포해야 합니다.

## 미션 측정

- UT_missions: 미션 시작·성공 시각, 전체 경과 초(total_seconds), 실제 조작 초(active_seconds), 첫 필터 조작 초(first_filter_seconds), 최근 정비 필터 첫 사용 초(first_recent_filter_seconds).
- UT_events: 참가자당 한 행에 지도 → 필터 → 최근 정비 켜기 → 자전거 마커 → 상세 정보처럼 실제 경로를 표시합니다. 원본 이벤트는 숨김 탭 UT_event_store에 보존합니다. 지도 드래그는 수집하지 않습니다.
- 측정은 프로토타입 준비 시 시작하며 참가자에게 시간은 표시하지 않습니다. 미션 팝업 또는 가려진 탭에서는 실제 조작 시간을 멈춥니다. 두 상태가 겹쳐도 중복 차감하지 않습니다.
- 검은색 ‘미션 보기’ 칩은 현위치 버튼과 수직 중심을 맞춥니다. 닫기 또는 Escape로 팝업을 닫으면 측정을 재개합니다.
- UT와 무관한 버튼은 화면 반응 없이 클릭 사실만 기록합니다.
- 필터 발견은 실제 첫 사용 기준입니다. 최근 정비·100m 이내·50% 이상 중 어떤 필터든 한 번 켜면 ‘발견’입니다. 종료까지 켜지 않으면 ‘발견하지 못함’, 진행 중 아직 켜지 않았다면 ‘미확인’입니다.
- 로그는 5초 간격으로 체크포인트를 저장하고, 서버 응답 확인 후 다음 묶음을 전송합니다. 이벤트 ID로 중복을 제거합니다. 네트워크가 끊기면 같은 브라우저 세션에서 재시도합니다. 브라우저를 강제 종료하면 마지막 미전송 기록은 시트에 남지 않을 수 있습니다. 종료 사실이나 미발견을 임의로 확정하지 않고 running 상태와 마지막 저장값을 유지합니다.
- P03은 미션 측정 연결 테스트 데이터입니다. 실제 참가자 응답에서 제외하세요.

## 순위 응답과 모바일 보정

복수응답(Q5·Q6)은 중요한 순서대로 1~3개를 선택합니다. 선택 순서대로 번호를 표시하고, 취소하면 남은 순위를 재정렬합니다. criteria_rank_1~3, usage_rank_1~3에 저장하며 선택하지 않은 순위는 비워 둡니다. 사전 Q6 선택 조건 선지는 거리, 배터리, 정비 상태, 예상 이용 요금, 주행 성능 및 승차감, 반납 가능 지역, 기타입니다.

모바일 터치 브라우저(599px 이하, pointer:coarse)에서 자전거 거리 라벨은 11px, 이용 거리·시간 칩은 13px입니다. PC의 폰트 크기는 유지합니다. 단일 선택 표시는 중앙의 원형 점, 복수 선택 표시는 중앙의 순위 숫자로 표시합니다. 스타일과 설문 파일 및 프로토타입 진입 주소에 버전을 붙여 이전 캐시 사용을 줄였습니다.

2026-11-03 순위/경로 저장 검증 응답 P04는 테스트 데이터로 표시되어 있습니다.

## 화면 문구·진행 속도

선택 개수 앞 구분점 및 완료 화면의 참가자 ID를 제거했습니다. 미션 안내와 팝업은 동일한 조건 1·조건 2 태그와 잠금해제 요청을 사용합니다. ID 발급은 연령대 선택 시 백그라운드에서 시작하며 문항 전환을 막지 않습니다. 로그는 발급 완료 후 전송하고 마지막 제출은 서버 저장 성공 확인 후 완료 처리합니다. 필터 경로에는 중복 분류명 대신 ‘최근 정비 켜기’ 등 실제 필터 이름만 표시합니다.

정답과 오답 모두 잠금해제 시 측정을 종료합니다. 오답의 mission_status는 failure이며 경로에 미션 종료 (오답)으로 표시합니다. 설문·미션 태그의 구분용 가운뎃점을 제거했고, 복수응답 안내의 두 문장은 연결하며 선택 개수 앞에만 강제 줄바꿈을 둡니다.
